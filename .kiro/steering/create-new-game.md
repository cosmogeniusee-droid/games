# Создание новой игры

Этот репозиторий — набор самостоятельных обучающих мини-игр для детей (чтение, счёт, внимание). Каждая игра — отдельная папка со статическими HTML/JS/CSS. Нет сборки, нет зависимостей кроме CDN (Bootstrap). Игры открываются прямо в браузере и публикуются на GitHub Pages.

Когда пользователь просит создать новую игру, следуй этому шаблону, чтобы она была единообразна с существующими (`SyllableTrain`, `FindChar`, `NumberHouses`, `MathTrain`).

## Обязательные принципы

- **Язык интерфейса — русский.** Все заголовки, подписи, кнопки, сообщения — на русском. Код/комментарии можно на английском, но пользовательский текст всегда русский.
- **Только статика.** Чистый HTML + ванильный JS + CSS. Никаких фреймворков в игре (Bootstrap — только на странице конфигуратора через CDN). Никакого шага сборки.
- **Паттерн «конфигуратор → URL → игра».** Настройки передаются в игру через query-параметры URL. Конфигуратор строит ссылку и показывает живое превью в `<iframe>`.
- **Детская визуальная стилистика.** Крупные элементы, яркие цвета, скруглённые углы, эмодзи, анимации (shake при ошибке, фанфары/анимация при победе).
- **Без клавиатуры, где уместно.** Для малышей предпочитай выбор по клику или drag-and-drop (с поддержкой касаний через Pointer Events), а не ввод с клавиатуры.
- **Не добавляй юнит-тесты.** Проверяй логику разовым прогоном (например `node -e "..."`) и убеждайся, что игра открывается в браузере. Не создавай тестовых файлов и тестовых проектов.

## Структура папки

Создавай новую папку в корне репозитория. Минимальный набор:

```
НазваниеИгры/
  index.html     — сама игра
  config.html    — конфигуратор с превью
  style.css      — (необязательно) если стили большие; иначе можно встроить <style> в index.html
  script.js      — (необязательно) если логика большая; иначе можно встроить <script> в index.html
```

Оба подхода встречаются в репозитории:
- Отдельные файлы: `FindChar`, `NumberHouses` (есть `style.css` и `script.js`).
- Всё в одном `index.html` со встроенными `<style>`/`<script>`: `SyllableTrain`, `MathTrain`.
Выбирай по объёму: небольшая игра — один файл, крупная — раздели.

## index.html (игра)

Типовой каркас:

```html
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Название игры</title>
    <!-- стили: либо <link rel="stylesheet" href="style.css">, либо встроенный <style> -->
</head>
<body>
    <!-- Заголовок с эмодзи, область игры, счётчики (время/ошибки/счёт), кнопки -->
    <!-- Стартовый оверлей и/или кнопка «Начать игру» -->
    <!-- Оверлей победы с кнопкой «Ещё раз» -->
    <!-- скрипт: либо <script src="script.js">, либо встроенный -->
</body>
</html>
```

Читай параметры в начале скрипта и давай каждому разумное значение по умолчанию:

```js
const params = new URLSearchParams(window.location.search);
const SIZE = parseInt(params.get('size') ?? '10', 10);
```

Полезные общие элементы (переиспользуй из существующих игр):
- Полноэкранный режим — кнопка, вызывающая `requestFullscreen()` / `exitFullscreen()`.
- Таймер в формате ММ:СС и/или счётчик ошибок, счёт.
- Анимация ошибки `@keyframes shake`, зелёная подсветка правильного ответа.
- Звук через Web Audio API (клик, ошибка, фанфары) — рабочий образец в `SyllableTrain/index.html` и `MathTrain/index.html`. Инициализируй `AudioContext` внутри жеста пользователя (клик по «Начать»), чтобы разблокировать звук на мобильных.
- Фон, настраиваемый параметром `bgcolor` (hex без `#`).

### Масштабирование под размер

Если в игре есть крупные элементы, завязывай все размеры на одну CSS-переменную (как `--car` в `MathTrain` или `--house-cell` в `NumberHouses`), чтобы менять масштаб одной строкой и держать пропорции. Добавляй `@media` брейкпоинты для узких экранов.

## config.html (конфигуратор)

- Подключи Bootstrap 5 по CDN (возьми тег `<link>` из любого существующего `config.html`).
- Слева — панель настроек (ползунки `range`, чекбоксы, цвет, текстовые поля). Справа — живое превью в `<iframe>`.
- Любое изменение настройки вызывает `updateLink()`, которая:
  1. собирает `URLSearchParams`, добавляя параметр **только если он отличается от значения по умолчанию** (чтобы ссылки были короткими);
  2. формирует `previewUrl` (относительный) и `fullUrl` (абсолютный на GitHub Pages);
  3. обновляет поле ссылки, кнопку «Открыть игру» и `previewFrame.src`.
- Абсолютная ссылка имеет вид:
  `https://cosmogeniusee-droid.github.io/games/НазваниеИгры/index.html?...`
- В превью (`previewFrame.src`) используй **относительный** `previewUrl`, чтобы превью работало и локально.
- Кнопка «Копировать» копирует полную ссылку в буфер обмена.
- Если игра поддерживает свои (заданные вручную) данные — дай текстовое поле; при его заполнении скрывай блок случайных настроек (пример — поле «Свои примеры» в `MathTrain`).

## Регистрация в README

Добавь ссылку на конфигуратор новой игры в `README.md` в общий список:

```
* [Название игры](/НазваниеИгры/config.html)
```

## Проверка перед завершением

1. Логику-ядро (генерация задач, подбор вариантов, граничные случаи) прогони разово через `node -e "..."` и убедись в корректности (без отрицательных/вне-диапазона значений, правильный ответ всегда присутствует и т.п.).
2. Убедись, что `config.html` строит корректную ссылку и превью открывает игру.
3. Проверь значения по умолчанию: игра должна работать и без параметров (`index.html` без query-строки).
4. Удали временные проверки; тестовых файлов не оставляй.
